# СТОКМЕД — MVP 0.1

Демонстрационный веб-дашборд для импорта Excel/CSV, базового прогноза потребности на 3 месяца, оценки обеспеченности и приоритизации запасов.

## 1. Запуск в VS Code

Требуется Python 3.10+.

### Windows PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
streamlit run app.py
```

Если PowerShell запрещает активацию окружения, можно запускать так:
```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Streamlit откроет локальную страницу в браузере.

## 2. Структура входного файла

Обязательные столбцы:
- `item_name` — наименование позиции
- `current_stock` — фактический остаток
- `avg_monthly_usage` — среднемесячный расход, используется если история не предоставлена
- `unit_price` — цена за единицу, руб.
- `lead_time_days` — срок поставки, дней
- `contract_available` — доступный остаток по действующим договорам
- `expected_delivery` — подтверждённые ожидаемые поставки
- `additional_requests` — дозаявки/резерв, которые нужно вычесть из доступного количества
- `planned_purchase_qty` — другие подтверждённые закупки, не учтённые в договорном остатке
- `criticality` — `высокая` или `обычная`

Необязательные столбцы истории расхода имеют формат `usage_ГГГГ_ММ`, например `usage_2026_07`. Добавляйте месяцы от старых к новым. При отсутствии истории используется `avg_monthly_usage`.

**Важно:** значения `contract_available`, `expected_delivery` и `planned_purchase_qty` должны быть непересекающимися. Не учитывайте одну и ту же поставку дважды.

## 3. Что делает прототип

- загружает CSV и Excel;
- проверяет обязательные поля, пустые, отрицательные и нечисловые значения;
- рассчитывает прогноз на 3 месяца простым базовым методом;
- оценивает обеспеченность, запас в днях, ориентировочную дату дефицита и страховой запас;
- присваивает красный/жёлтый/зелёный приоритет и рекомендацию;
- показывает сводные показатели и график «факт + прогноз»;
- экспортирует расчёты в Excel.

## 4. Ограничения текущей версии

Это MVP для демонстрации и проверки гипотез, а не готовая клиническая или складская система:
- модель прогноза пока базовая, сезонность полноценно не обучается;
- дата дефицита считается по суммарной расчётной обеспеченности, без календарного моделирования каждой поставки;
- правила приоритета и формулы нужно согласовать с заказчиком;
- MAPE и сравнение с текущим методом нужно проверить ретроспективно на обезличенной истории до заявления о достижении KPI;
- нет пользователей/ролей, аудита действий, базы данных и облачного размещения.

Не загружайте персональные данные или неразрешённые данные медорганизации. Для пилота используйте обезличенные данные с разрешения заказчика.
